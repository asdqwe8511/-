# 선물 자동매매 봇 (Bybit USDT 무기한, 모의 단계)

사주 웹앱과 별개인 폴더입니다. 의존성 없이 Node 18+ 만 있으면 됩니다.
**아직 실주문 코드는 없습니다.** 백테스트와 실시간 모의(공개 시세만 사용)까지입니다.

## 규칙 → 코드

| # | 규칙 | 구현 |
|---|------|------|
| 1 | 가장 강한 지지/저항에 트리거, 모든 코인 | `lib/levels.js` 일봉 전체(최대 1000개) 피벗을 1% 폭으로 묶고 터치 수·최근성·거래량으로 강도 산정. 현재가 아래 최강 지지 = 롱 트리거, 위 최강 저항 = 숏 트리거. 하루 1회 갱신 |
| 2 | 진입가 대비 ±10% 방향 적중 시 손절선만 설정 (익절 없음, 물량 100% 유지) | `lib/strategy.js` OPEN→LOCKED. 손절선 = 최대 이익의 50% 지점 (+10%면 +5%) |
| 3 | 스탑은 1일 1회만 수정 | 24시간마다 최고 이익의 50% 지점으로 재계산, 유리한 방향(롱은 위, 숏은 아래)으로만 이동 |
| 4 | 첫 진입 격리, 시드의 1/10 | `config.js` `seed / entryDivisor` 가 증거금 |
| 5 | 첫 진입은 스탑 없이 청산까지 | OPEN 단계엔 스탑이 없고, 손절선이 생기기 전까지는 청산으로만 끝남 |

모든 숫자(레버리지, 동시 포지션 상한, 수수료 등)는 `config.js` 에서 바꿉니다.

## 트리거 개수·종목

- USDT 정산 무기한 계약만 대상입니다 (`/^[A-Z0-9]+USDT$/`, USDC·만기물 제외).
- 코인마다 트리거는 **롱 1개(최강 지지선) + 숏 1개(최강 저항선)** 뿐이고, 하루 1회 갱신 때 교체합니다. 포지션이 열리면 그 코인의 대기 트리거는 없습니다. 코인당 2개라 거래소 대기 주문 개수 제한에 걸릴 일이 거의 없습니다.
- 트리거 주문 수량 한도(시장가 조건부는 지정가보다 작음)와 리스크 한도는 실주문 단계에서 코인별 `instruments-info`·`risk-limit` 로 확인해 수량을 맞춥니다. 진입 규모가 시드의 1/10 이라 대부분 해당되지 않습니다.

## 실행

```bash
npm run test:bot                  # 로직 테스트 (네트워크 불필요)
node trading-bot/backtest.js 30   # 거래대금 상위 30코인, 최근 ~41일 1시간봉
node trading-bot/paper-bot.js 50  # 실시간 모의 (15초마다 시세, 상태는 paper-state.json)
```

Bybit 공개 API(`api.bybit.com`)에 접속되는 환경에서 돌려야 합니다.

## 알아둘 것

- **스탑 없는 진입 = 손실 상한은 격리 증거금(시드의 1/10)** 입니다. 레버리지 5배면 진입가에서 약 -19.5% 근처에서 청산됩니다. 레버리지를 올리면 청산이 가까워져 "청산까지 방치"가 곧 전액 손실이 됩니다.
- 코인을 전부 감시해도 1/10씩이라 **동시 포지션은 `maxOpen` 개까지**만 엽니다. 수수료 때문에 10번째 칸은 증거금이 모자랄 수 있습니다.
- +10%는 레버리지 5배면 증거금 대비 +50% 입니다. 반대로 -10%에서는 아무것도 하지 않습니다.
- 손절선은 하루 1번만 올라가므로, 하루 안에 급반전하면 올라가기 전 손절선(처음엔 이익 5%)까지 되돌려 맞습니다. 주기를 줄이면 더 촘촘히 지키지만 규칙3과 달라집니다.
- 백테스트는 1시간봉 안에서 시가→저/고→종가 순서로 가정하고, 트리거는 선 가격에 슬리피지만 얹어 체결합니다. 실제보다 낙관적일 수 있습니다.
- 지지/저항 방식(반등 진입)은 추세장에서 선이 뚫리면 계속 불리합니다. 백테스트로 먼저 확인하세요.

## 실주문 (`live-bot.js`)

```bash
export BYBIT_API_KEY=... BYBIT_API_SECRET=...          # 거래 권한만, 출금 권한 끄기, 전용 서브계정 권장
node trading-bot/live-bot.js                            # 테스트넷 + 드라이런(주문 안 냄, 트리거 계산만 로그)
LIVE_ORDERS=1 node trading-bot/live-bot.js              # 테스트넷에 실제 주문
# 메인넷: BYBIT_ENV=mainnet BYBIT_MAINNET_CONFIRM=I-ACCEPT-REAL-MONEY-RISK LIVE_ORDERS=1 node trading-bot/live-bot.js
touch trading-bot/STOP                                  # 중단: 대기 트리거 전부 철회하고 종료 (열린 포지션은 그대로)
```

동작: 하루 1회 일봉으로 선을 계산 → 코인마다 조건부 시장가 롱/숏 1개씩 등록 → 10초마다 거래소 포지션을 읽어 체결을 확인
(체결되면 그 코인의 남은 트리거 취소) → +10%가 되면 `trading-stop` 으로 이익 50% 지점 손절 설정, 하루 1회 상향 →
포지션이 끝나면 쿨다운. 포지션 상한(`maxOpen`)에 닿으면 대기 트리거를 전부 거둡니다. 상태는 `live-state.json` 에 저장되고,
상태 파일이 없어도 거래소 포지션을 읽어 이어받습니다. 이 봇이 낸 주문은 `orderLinkId` 가 `sb-` 로 시작하는 것만 만지고,
24h 거래대금 100만 USDT 미만 코인과 최대 레버리지가 설정 배율보다 낮은 코인은 건너뜁니다(`config.js`).

**테스트넷에서 먼저 확인할 것 — 이 환경에서는 Bybit 에 접속이 안 돼 실제 API 응답으로는 검증하지 못했습니다.**
로직은 가짜 거래소로 테스트했지만 아래는 실제 응답으로 확인이 필요합니다.
- 계정 마진모드 전환(`/v5/account/set-margin-mode`)이 **계정 전체**에 적용됩니다. 실패하면 코인별 격리 전환으로 대체하지만 그 경로도 미검증입니다. 그래서 전용 서브계정을 권합니다.
- 원웨이 모드(`positionIdx 0`) 전제입니다. 헤지 모드 계정이면 주문이 거절됩니다.
- 조건부 주문의 트리거 방향·수량 한도·건수 제한, `trading-stop` 이 이미 지난 가격을 거절하는 동작(봇은 직접 시장가 청산으로 대응).
- 모든 코인에 트리거를 깔면 급락·급등장에서 **여러 개가 한꺼번에 발동**할 수 있습니다. 상한 확인은 10초 주기라 그 사이 `maxOpen` 을 넘겨 열릴 수 있고, 잔고가 모자라면 거래소가 거절합니다.
- 최고가는 10초 폴링으로 추적하므로 그 사이의 순간 고점은 놓칩니다(스탑이 조금 낮게 잡힘). 거래소에 걸린 스탑 자체는 틱 단위로 체결됩니다.
- 이 계정의 기존 USDT 무기한 포지션(수동 진입 포함)도 봇이 인수해 스탑을 겁니다. 전용 계정에서만 돌리세요.
