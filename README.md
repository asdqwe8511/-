# 인기영상 대시보드

YouTube의 국가별 실시간 인기영상과 채널 정보를 보여주는 공개 웹 대시보드입니다.

- 로그인 없이 누구나 바로 볼 수 있습니다.
- YouTube API 키는 서버(Vercel 환경변수)에만 있고 브라우저에는 절대 노출되지 않습니다.

두 개의 페이지가 한 프로젝트에 들어 있습니다.

| 경로 | 내용 |
|---|---|
| `/` | 사주팔자 + 이름 풀이 + 돈·건강·관계 시기 + 궁합 + 연락처 일괄 비교 |
| `/youtube` | YouTube 국가별 인기영상 대시보드 |

예전에 공유된 `/saju` 주소는 `/` 로 넘겨 줍니다(`vercel.json` 의 redirects).

## 아키텍처

```
index.html              사주·이름 풀이 UI 전체 (사이트 메인)
youtube.html            인기영상 대시보드 UI 전체
saju-engine.js          만세력·오행·성명학·궁합 계산 엔진.
                         브라우저와 서버가 같은 파일을 씁니다.
api/saju.js             사주 해석 엔드포인트. 서버가 직접 계산한 뒤 그 결과만
                         Claude 에게 넘기고 응답을 스트리밍합니다. 사용량 제한도 여기서.
api/yt/[...path].js     YouTube Data API 프록시.
                         - 허용된 읽기 엔드포인트(videos/videoCategories/channels)만 전달
                         - 성공 응답은 Vercel 엣지에서 30분간 캐시
                         - 여기서만 YouTube API 키를 사용
og-saju.png             사주 페이지 링크 미리보기 이미지
og-image.png            인기영상 대시보드 링크 미리보기 이미지
favicon.png             브라우저 탭 아이콘
robots.txt, sitemap.xml 검색 노출
tools/make-og-saju.py   사주 미리보기 이미지 생성
tools/make-og.py        대시보드 미리보기 이미지·파비콘 생성
tools/dev-server.js     PC용 개발 서버
tools/test-saju.js      만세력·궁합·연락처 계산 점검
tools/test-quota.js     사용량 제한 점검
vercel.json             깔끔한 URL, /saju → / 리다이렉트, 함수 실행 시간 제한
```

브라우저는 `googleapis.com`을 직접 호출하지 않고 항상 `/api/yt/...`를 거칩니다.

### 할당량 보호

사이트가 공개되어 있으므로 프록시도 누구나 호출할 수 있습니다. 두 가지로 방어합니다.

1. **엔드포인트 허용 목록** — 임의의 구글 API로 중계할 수 없습니다.
2. **엣지 캐싱** — 성공 응답을 30분간 CDN에 캐시합니다. 방문자가 몇 명이든
   YouTube 호출량은 거의 일정하게 유지되므로, 로그인이 있던 때보다 오히려
   할당량을 적게 씁니다.

## PC에서 실행하기

Node.js 18 이상이 필요합니다.

```bash
# 저장소 이름이 "-" 라서 받을 폴더 이름을 직접 정해 줘야 합니다.
# 안 그러면 폴더 이름이 - 가 되어 cd 가 이전 디렉터리로 이동해 버립니다.
git clone https://github.com/asdqwe8511/-.git saju
cd saju

npm install                 # 사주 해석(Claude 호출)에만 필요합니다
node tools/dev-server.js     # http://localhost:3000
```

git 이 없다면 GitHub 페이지에서 **Code → Download ZIP** 으로 받아 풀어도 됩니다.

`tools/dev-server.js` 는 의존성 없는 개발 서버로, Vercel 이 해 주던 일 중 세 가지를
흉내 냅니다 — 확장자 없는 주소(`/saju`), `req.query` 파싱, JSON 본문을 `req.body` 로 파싱.
`api/` 아래 함수도 그대로 불러 줍니다.

API 키는 프로젝트 폴더에 `.env` 파일을 만들어 넣으면 읽어 갑니다(`.gitignore` 에 있어
커밋되지 않습니다).

```
ANTHROPIC_API_KEY=sk-ant-...
YOUTUBE_API_KEY=...
```

**키가 없어도 사주표·오행·대운·시기·이름·궁합·연락처 비교는 전부 동작합니다.**
Claude 가 쓰는 해석 문장만 나오지 않고, 그 자리에 안내와 다시 시도 버튼이 뜹니다.

## 사주·이름 풀이는 어떻게 계산하나

절기표나 음력표를 파일로 싣지 않고, `saju-engine.js` 가 천문 계산으로 직접 구합니다.

- **태양 황경** — VSOP87 지구 황경 급수를 절단해 씁니다(오차 ±0.001° 수준).
  절입 시각이 실제와 1분 안쪽으로 맞습니다. 저정밀 공식은 5~8분씩 어긋나는데,
  절입 직전에 태어난 사람은 그 몇 분에 월주와 연주가 통째로 바뀝니다.
- **연주** — 1월 1일이 아니라 입춘을 기준으로 넘어갑니다.
- **월주** — 출생 순간의 태양 황경으로 바로 판정합니다(입춘 315°부터 30°씩).
- **일주** — 율리우스일 기반 60갑자. 1949-10-01 = 갑자일, 2000-01-01 = 무오일로 검증했습니다.
- **시주** — 진태양시(경도차 + 균시차)로 보정합니다. 서울은 표준시보다 약 32분 빠릅니다.
  1954~1961년의 UTC+8:30, 1948~1988년의 서머타임 구간도 되돌립니다.
- **음력** — 삭(신월) 시각과 중기(中氣)로 직접 만듭니다. 동지가 든 달이 11월이고,
  두 동지 사이에 열세 달이 있으면 중기가 없는 첫 달이 윤달입니다.
  1930~2026년의 모든 날짜에 대해 양력↔음력 왕복이 일치하고, 윤달 연도도 실제와 맞습니다.

여기까지는 **계산**이라 재현됩니다. 반면 신강·신약 판정, 용신 선택, 81수리 길흉은
유파마다 기준이 다른 **해석**이며, 널리 쓰이는 한 가지 방식을 골라 구현한 것입니다.
페이지에도 그렇게 적어 두었습니다.

성명학은 한글 자모 획수와 초성의 발음오행(ㄱㅋ=목, ㄴㄷㄹㅌ=화, ㅇㅎ=토, ㅅㅈㅊ=금, ㅁㅂㅍ=수)을
씁니다. 한자 획수법과는 기준이 다릅니다.

### 좋은 시기 · 조심할 시기

메인 페이지는 돈·건강·관계 세 갈래로 해마다 점수를 매기고, 연속된 해를 하나의 시기로 묶어
좋은 시기 TOP 3와 조심할 시기 TOP 3를 보여 줍니다. 계산 재료는 세 가지입니다.

1. **십신** — 그 해 세운(과 배경이 되는 대운)의 천간·지지가 일간에게 무엇인지.
   같은 재성이라도 신강한 사람에게는 벌이가 되고 신약한 사람에게는 짐이 되므로,
   점수표는 `[신강일 때, 신약일 때]` 두 값을 갖습니다.
2. **오행 균형** — 용신·희신이 드는 해는 올리고 기신이 드는 해는 내립니다.
   이 비중은 영역마다 다릅니다. 건강은 일간의 균형 자체가 주제라 가장 무겁고,
   재물은 균형보다 재성·식상이 오는지가 먼저입니다.
3. **형충회합** — 세운 지지가 원국의 네 지지와 맺는 관계(육합·삼합·방합·충·형·해·파·원진).
   일지가 가장 무겁고, 인연은 합충에 가장 민감합니다.

여기에 영역별 신호가 더해집니다 — 식상생재와 군겁쟁재(재물), 일지 육합과 도화(관계),
기신 겹침과 편관 중첩(건강).

점수는 **그 사람의 일생 안에서 0~100으로 환산한 상대값**입니다. 남과 비교하는 값이 아닙니다.
같은 지지가 12년마다 돌아오면 같은 이유로 다시 걸리므로, 시기를 고를 때 1차로는 지지가
겹치지 않는 구간부터 채웁니다("술년" 세 줄이 나오지 않도록).

세 갈래가 같은 해를 가리키는 일이 잦습니다. 원국을 잘 받쳐 주는 해는 대체로 전반이 함께
좋아지기 때문이고, 차이는 주로 조심할 시기 쪽에서 갈립니다.

**이 점수는 계산이 아니라 해석입니다.** 억부·조후 관점을 수치로 옮긴 것이고 유파에 따라
다르게 볼 수 있습니다. 특히 건강은 진단이 아니라 생활 관리의 관점으로만 다룹니다.

### 궁합 — 두 사람 견주기

**둘이 보기** 는 두 사람의 원국을 네 축으로 견줍니다.

| 축 | 무엇을 보는가 |
|---|---|
| 끌림 | 일간·일지가 서로 당기는가 (천간합, 육합, 삼합, 충) |
| 안정 | 서로 모자란 오행을 채워 주는가, 힘의 세기와 계절이 맞물리는가 |
| 소통 | 상대가 나에게 어떤 십신인가, 두 이름의 소리가 어울리는가 |
| 지속 | 오래 두었을 때 갈리는 자리가 얼마나 있는가 (충·형·해·파·원진) |

축 점수는 50에서 시작해 항목을 더하고 뺀 값이고, **어떤 항목이 몇 점을 움직였는지
그대로 화면에 보여 줍니다.** 총점 하나만 던지면 84점과 61점의 차이를 아무도 알 수 없습니다.

네 축을 가중평균한 원점수는 대개 45~70에 몰려서, 그대로 내놓으면 누구와 붙여도
비슷해 보입니다. 그래서 **무작위로 짝지은 48,180쌍의 분포에 견주어 백분위로 환산**합니다.
궁합 70점은 100점 만점의 70점이 아니라 "무작위로 만난 상대 100명 중 상위 30번째" 라는 뜻입니다.

### 여러 명과 비교 — 연락처 불러오기

**카카오톡은 친구 생일을 내보내는 기능이 없습니다.** 공개 API도, 내보내기 메뉴도 없어서
어떤 방법으로도 가져올 수 없습니다. 대신 휴대폰·구글 연락처에서 내보낸 파일을 읽습니다.

- **vCard(.vcf)** — 아이폰/안드로이드/구글 공통. `BDAY` 필드를 읽습니다.
- **CSV** — 구글 연락처, 아웃룩. 머리글에서 이름·생일 열을 찾습니다.
- **직접 붙여넣기** — `홍길동 1990-05-15` 같은 줄 목록.

**파일은 브라우저 안에서만 열리고 서버로 전송되지 않습니다.** 파싱도 궁합 계산도 전부
`saju-engine.js` 가 브라우저에서 합니다. 연락처에는 태어난 시각이 없으므로 시주 없이
계산하며, 화면에도 그만큼 거친 비교라고 적어 둡니다. 연도가 없는 생일(`--MMDD`)은
사주를 세울 수 없어 건너뛰고, 몇 명이 왜 빠졌는지 보여 줍니다.

### 궁합 링크

**둘이 보기** 화면에서 내 사주를 담은 링크를 만들어 상대에게 보낼 수 있습니다. 상대는
링크를 열고 자기 생년월일만 넣으면 바로 궁합을 봅니다. 카카오톡·문자 어디에 붙여넣어도
되도록 링크는 130자 안팎입니다.

사주는 URL 의 **프래그먼트(`#invite=...`)** 에 base64url 로 담깁니다. 브라우저는 `#` 뒤를
서버로 보내지 않으므로, 링크가 이 사이트를 지나가도 **생년월일이 서버 로그에 남지 않습니다.**
저장소도 없고 계정도 없습니다.

바꿔 말하면 이런 한계가 있고, 화면에도 그대로 적어 두었습니다.

- 링크를 가진 사람은 누구나 담긴 생년월일과 이름을 볼 수 있습니다.
- 서버에 저장하지 않으므로 **한 번 보낸 링크는 회수할 수 없습니다.**
- 이름은 빼고 생년월일시만 담는 선택지를 둡니다.

링크로 들어온 값은 남이 만든 데이터이므로, 폼에 넣기 전에 연도 범위·성별·한글 이름 형식을
검사합니다. 서버(`api/saju.js`)에서도 같은 검사를 한 번 더 합니다.

### 해석 문장

계산 결과를 `api/saju.js` 가 문장으로 정리해 Claude 에게 넘기고, 응답을 그대로 스트리밍합니다.
브라우저가 보내는 것은 생년월일·성별·이름 같은 원자료뿐이고, 전부 형식 검증을 통과해야 합니다
(이름은 한글만 허용). 자유 문장이 프롬프트에 닿는 경로가 없습니다.

## 환경변수

Vercel 프로젝트의 **Settings → Environment Variables** 에 넣습니다.

| 이름 | 필요한가 | 쓰는 곳 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 풀이 문장을 쓰려면 필수 | `/` 의 풀이 |
| `YOUTUBE_API_KEY` | 대시보드를 쓰려면 필수 | `/youtube` |
| `UPSTASH_REDIS_REST_URL` | 공개 운영이면 사실상 필수 | 사용량 제한 |
| `UPSTASH_REDIS_REST_TOKEN` | 위와 한 쌍 | 사용량 제한 |
| `SAJU_DAILY_LIMIT` | 선택 (기본 300) | 하루 총 풀이 횟수 |
| `SAJU_IP_HOURLY_LIMIT` | 선택 (기본 10) | 한 사람이 한 시간에 부를 수 있는 횟수 |
| `SAJU_IP_SALT` | 선택 | IP 해시에 섞는 값 |

키가 하나도 없어도 **사주표·오행·대운·시기·이름·궁합·연락처 비교는 전부 동작합니다.**
계산이 브라우저에서 끝나기 때문입니다. 풀이 문장 자리에만 안내가 뜹니다.

## 토스 미니앱(앱인토스)에 올릴 때

앱인토스는 **WebView 방식**과 **React Native(Granite)** 두 가지를 지원합니다.
WebView 는 배포된 웹사이트 URL 을 그대로 띄우므로, **이 사이트를 다시 만들 필요가 없습니다.**

이 페이지는 그 전제로 **모바일 퍼스트**로 짜여 있습니다.

- 한 화면에 한 단계만 묻는 4단계 입력 (생년월일 → 시각 → 성별·이름 → 궁합)
- 하단 고정 실행 버튼, `env(safe-area-inset-*)` 로 노치·홈바 피하기
- 입력 글자 16px (iOS 가 그 아래에서 자동 확대를 걸어 화면이 튄다)
- 터치 영역 최소 44~56px, `overscroll-behavior` 로 웹뷰의 당겨서 새로고침 차단
- 넓은 화면에서도 같은 폭(520px)을 가운데 둬서 어디서 열든 같은 앱으로 보이게

### 심사에서 조심할 것

토스는 **민감한 주제를 점수화한 서비스**에 엄격한 기준을 적용하고, 기존 미니앱도
재검수합니다. 그래서 이 페이지는 **계산은 안에서 0~100 으로 하되 화면에는 숫자를 내지
않습니다.**

| 안에서 | 화면에 |
|---|---|
| 궁합 총점 73 | "잘 맞는 편" |
| 끌림 61 | "강한 편" |
| 재물 시기 88 | "아주 좋은 편" |
| 일간 지지율 0.64 | "뿌리가 단단한 편" |

'건강' 은 **'몸·리듬'** 으로 부르고, '좋은/조심할 시기' 는 **'힘이 실리는 시기 / 속도를
늦출 시기'** 로 씁니다. 풀이 문장을 만드는 프롬프트에도 같은 규칙을 넣어, 모델이
"궁합 73점" 같은 표현을 쓰지 않도록 막았습니다.

### 수익 구조

원가가 이미 둘로 갈려 있습니다.

- **계산**(사주표·오행·대운·시기·이름·궁합) — 브라우저에서 처리, **원가 0원**
- **풀이 문장**(Claude) — 1회당 요금 발생

그래서 풀이는 결과가 나오자마자 자동으로 부르지 않고, **잠금 카드와 버튼 뒤**에 둡니다
(`prepareReading` → `startReading`). 결제를 붙일 때는 `startReading` 앞에 결제 확인만
끼우면 되고, 계산 결과는 그대로 무료로 보입니다.

> 결제·광고·토스로그인을 쓰려면 **사업자 등록**이 필요합니다. 미니앱 등록과 심사는
> 앱인토스 개발자센터에서 직접 진행해야 합니다.

## 공개 운영 — 요금이 새지 않게

`/api/saju` 는 부를 때마다 Claude API 요금이 나갑니다. 사이트가 공개되어 있으니
누구든 반복해서 부를 수 있고, 서버리스는 인스턴스가 여러 개라 메모리 카운터로는
막히지 않습니다. 그래서 **Upstash Redis(REST)에 공용 카운터**를 둡니다.

- 하루 총 풀이 횟수 (`SAJU_DAILY_LIMIT`, 기본 300)
- 한 사람이 한 시간에 부를 수 있는 횟수 (`SAJU_IP_HOURLY_LIMIT`, 기본 10)

상한에 걸리면 429 와 함께 안내가 뜨고, **계산 결과는 그대로 보입니다** —
풀이 문장만 나오지 않습니다. IP 는 그대로 저장하지 않고 해시한 값만 최대 이틀간
둡니다. Redis 가 설정되지 않았거나 잠시 응답하지 않으면 통과시킵니다(fail-open) —
사이트가 통째로 멈추는 것보다 낫기 때문입니다.

> **마지막 방어선은 Anthropic 콘솔의 지출 한도입니다.** 위 카운터는 정상적인 남용을
> 막는 장치일 뿐이니, console.anthropic.com 에서 월 지출 한도를 꼭 걸어 두세요.

Upstash 는 Vercel 대시보드의 **Storage → Upstash Redis** 에서 무료 티어로 붙일 수
있고, 붙이면 위 두 환경변수가 자동으로 들어갑니다.

동작 확인:

```bash
node tools/test-quota.js
```

Redis 와 Claude 를 가짜로 세워 두고 실제 핸들러를 부릅니다 — 상한에 걸리는지,
형식이 틀린 요청이 하루 분량을 깎지 않는지, Redis 가 죽었을 때 통과하는지,
IP 가 그대로 저장되지 않는지를 봅니다.

## 설정이 제대로 들어갔는지 확인하기

배포한 뒤 **`사이트주소/api/health`** 를 브라우저로 열면 무엇이 켜지고 무엇이 꺼졌는지
한눈에 보입니다.

```
사이트주소/api/health           키가 들어 있는지만 확인 (외부 호출 없음)
사이트주소/api/health?deep=1    키가 실제로 통하는지까지 확인
```

`?deep=1` 은 Anthropic 모델 목록 조회와 Redis PING 을 해 봅니다. **둘 다 요금이 붙지
않는 호출**이고, 응답에 키 값은 들어 있지 않습니다. 키를 넣었는데도 풀이가 안 나오면
여기서 `설정은 됐지만 연결 실패` 인지 `꺼짐` 인지부터 보세요 — 전자는 키가 틀린 것이고
후자는 환경변수가 안 붙은 것(대개 **Redeploy 를 안 한 것**)입니다.

로컬에서는 `.env.example` 을 `.env` 로 복사해 값을 채우면 됩니다.

## 만세력 계산 점검

```bash
node tools/test-saju.js
```

절기 시각, 60갑자 기준일, 입춘 기준 연주 전환, 시지 24개 경계, 음력 명절·윤달,
1930~2026년 양력↔음력 왕복을 알려진 값과 대조합니다. 운세 점수는 값 자체를 검증할 수
없으므로(해석이라서), 대신 구조를 봅니다 — 점수 범위, 시기 개수, 구간이 서로 겹치지 않는지,
좋은 시기가 조심할 시기보다 실제로 높은지, 형충회합 판정이 맞는지.
궁합은 축 점수 범위, 환산 점수가 원점수에 대해 단조 증가하는지(아니면 순위가 뒤집힙니다),
천간합 같은 알려진 관계가 실제로 잡히는지를 보고, 연락처는 vCard·CSV·붙여넣기 세 형식과
생일 표기 일곱 가지를 대조합니다.
