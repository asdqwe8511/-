# hanja-data.js 만드는 법

이름에 쓸 한자를 고르는 화면(`한자 고르기`)이 쓰는 표입니다. 저장소에는 결과물인
`hanja-data.js`(29KB)만 두고, 원자료는 두지 않습니다.

## 원자료

| 무엇 | 어디서 | 라이선스 | 쓰는 부분 |
|---|---|---|---|
| 한자 → 한글 음 | PyPI `hanja` 의 `hanja/table.yml` | MIT | 27,497자의 음 |
| 획수 | npm `hanzi-writer-data` | ARPHIC Public License | 글자별 획 데이터 개수 |

## 절차

```sh
pip download --no-deps -d /tmp/hj hanja && unzip -q /tmp/hj/hanja-*.whl -d /tmp/hj
npm pack hanzi-writer-data && mkdir -p /tmp/hw && tar xzf hanzi-writer-data-*.tgz -C /tmp/hw
```

그런 다음 파이썬으로:

1. `table.yml` 을 읽어 한자 → 음 표를 만든다.
2. **KS X 1001 만 남긴다.** 판별은 `c.encode('euc-kr')` 가 되는지로 한다.
   euc-kr 이 곧 KS X 1001 이라 별도 목록이 필요 없고, 중국 간체자가 저절로
   빠진다. 한글 워드프로세서의 한자 변환 목록과 같은 범위가 된다.
3. 음절별로 묶고, `hanzi-writer-data/<글자>.json` 의 `strokes` 길이를 획수로 붙인다.
4. 획수가 적은 것부터 정렬해 `글자획수글자획수…` 꼴의 한 줄로 잇는다.
   획수를 모르면 `?` 를 넣는다.

결과: 음절 462개 / 한자 4,621자 / 획수 확인 4,110자(88.9%).

## 채워지지 않는 획수

빠지는 511자는 대개 한국에서만 쓰는 글자(鎰·晸·柾·眞·鎭·姸·晙 …)로,
`hanzi-writer-data` 에 없습니다. 유니코드 Unihan 의 `kTotalStrokes` 를 쓰면
전부 채울 수 있습니다.

**손으로 채우지 않습니다.** 획수를 하나라도 잘못 적으면 수리(數理) 결과가 조용히
틀리고, 쓰는 사람은 그것을 알아챌 방법이 없습니다. 대신 화면에서 "획수 모름"으로
표시하고, 그런 글자가 하나라도 있으면 한자 획수로 셈하는 수리는 건너뜁니다.

## 획수의 갈래

여기 담긴 획수는 **필획**(실제로 긋는 획)입니다. 성명학에는 강희자전의 **원획**
(부수를 본래 글자 수로 세는 방식: 氵→4, 艹→6, 辶→7 …)을 쓰는 갈래도 있고,
두 갈래는 같은 이름에 다른 수리를 내놓습니다. 화면에서도 그 점을 밝힙니다.
